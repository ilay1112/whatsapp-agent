## 3. REQUESTS

### W2-01-compose-integration

1. **Install the frozen `__wcaTest` facade.** `src/main/testSeams.ts` already exports `installTestHooks(hooks)` with the
   exact eight hooks of TESTS 4.2 (`trayTemplate, trayClick, trayState, doorbellUrl, health, notifications,
   openedExternal, childPids`). `index.ts` instead installs an ad-hoc object with `tray/clickTray/health/notify`.
   `tests/e2e/helpers/fixtures.ts` calls the frozen name first and falls back to the current one, so every green spec
   stays green after the switch - but five hooks have no fallback at all:
   - `doorbellUrl()` - without it an attach-mode spec cannot ring the doorbell, so the specs currently rely on the 30 s
     ingest scan (shortened with `WCA_TIMERS.scanMs`). Works, but the doorbell path itself is then untested at L5.
   - `openedExternal()` - blocks test 5 above, and more importantly makes it **unsafe** to exercise the Google wizard at
     all: `ElectronFacade.notify` and `shell.openExternal` are the real ones even in e2e mode. Please replace both with
     recorders when `seams !== null` (TESTS 4.2 last row says so explicitly).
   - `notifications()` - the first-close coach mark is asserted through `meta.tray_hint_seen` + the in-window
     `coach-mark` element instead. Note that `installCloseToTray.onFirstHide` in `index.ts` never shows the toast that
     UX 12.2 asks for; only the in-window coach mark exists.
   - `trayState()` - the tray icon variants (`tray-error` / `tray-attention` / `tray-paused`) are therefore not asserted
     at L5. The menu, its status line and the Pause label are.
   - `childPids()` - fallback in place (`run\*.pid.json`), no test blocked.
2. **Wire `WCA_LLM` / `WCA_LLM_SCRIPT`.** This is the single biggest gap: without it the whole "the app drafts, the user
   approves, exactly one thing happens" half of `approval-first.spec.ts` cannot run in the built app. Your own notes
   already identify the hook (`ComposeDeps.providerOverride`). The fake must not be imported from `tests/**` at run time -
   a small scripted provider inside `testSeams.ts` (reading `WCA_LLM_SCRIPT`, which `readSeams` already parses) keeps the
   build-time lock intact. The two blocked tests are written out in full and will pass unchanged once it lands.
3. **Start the bridge when the ToS is accepted** (defect 4). `compose()` starts the bridge from `start()` and from the
   three `pairing:*` handlers only. On a fresh profile `start()` runs before the user has accepted, `consent:accept`
   records the consent and nothing else happens, so `Link WhatsApp` sits in the `preparing` panel for ever - and that
   panel has no button, so the user cannot recover. One `bridgeControl.start()` after a `whatsapp_tos` consent fixes it
   (either in the handler, or by having `consent:accept` emit an event compose listens to).
4. **Rebuild the tray on `language`** (defect 3): `if (key === 'health' || key === 'pairing' || key === 'language')
   tray?.rebuild();` in the event loop of `index.ts`. `compose()` already rebuilds its i18next instance and emits.
5. **Take the single-instance lock in e2e too** (defect 6): `requestSingleInstanceLock()` is per-`userData`, and every
   e2e launch already gets its own temp profile, so honouring it cannot make parallel specs collide - while bypassing it
   lets two full instances write one `app.db`.
6. **Honour `WCA_NOW`** - `readSeams` parses it, `index.ts` builds `realClock` from `Date.now()` and `compose()` never
   looks at `seams.now`. No spec depends on it today (the date-dependent scenarios are blocked by request 2 anyway), but
   TESTS 4.2 promises it for weekday-table determinism.
7. **`WCA_FOCUS_CHECK`** is parsed and unused as well. The hidden-window rejection is proven; an approval from a
   *visible but unfocused* window will need this the moment request 2 lands.

### W1-12-shell-main (or W2-01 under its fix-up right)

8. The CSP constant in `src/main/app/protocol.ts` carries `frame-ancestors`, which Chromium **ignores** in a `<meta>`
   tag and reports as a console **error** on every single boot. `tests/e2e/helpers/fixtures.ts` has to allow-list that
   one message for every launch, which weakens the "any renderer console error fails the spec" rule for all specs.
   Please move it to the response header (`registerAppProtocol`) or drop it from the meta tag.

### orchestrator / spec defects (no code change implied)

9. **TESTS 10 scenario (8), orphan reaping, is unreachable through the `WCA_BRIDGE_CMD` seam.** `parsePidFile` accepts an
   `exePath` only when it is inside the app's own resources dir or equal to the app's `execPath` (electron.exe); the seam
   child is the system `node.exe`, so an orphaned seam child is always discarded as *stale* instead of being reaped. The
   safety half (a live process a pid file points at is never killed, and the stale file is cleaned up) IS covered by
   `tray-lifecycle.spec.ts`; the kill path stays covered at L2 by W1-01. Either the spec text should say so, or the seam
   would have to record a resources-dir path, which would weaken `parsePidFile`. I did not weaken it.
10. **"first-run default from the seeded system language" (TESTS 9) cannot be driven on Windows.** `resolveLanguage`
    consumes `app.getPreferredSystemLanguages()`, which reads the OS setting; `LANG=he_IL.UTF-8` in the child env does
    nothing. `seedProfile({ settings: { language: 'he' } })` is used instead, which tests the same resolution path
    downstream of the OS. `systemLanguageEnv()` is left in `seedProfile.ts` for a future seam.
11. `historySync` is missing from the child-mode control server of `tests/fakes/fake-bridge.ts` (W1-02), so the 300-row
    history-sync scenario runs in ATTACH mode, where the fake object is in the test process. Not a blocker.

## 4. Decisions and assumptions worth knowing

- **Console errors are per-launch fatal**, with one global allow-list entry (request 8) and per-launch opt-ins
  (`app.spec.ts` deliberately provokes a CSP `connect-src` refusal).
- **`waitForTestHooks`**: `index.ts` installs `__wcaTest` as the very last step of `whenReady`, i.e. after
  `runtime.start()` has spawned the children. In child-bridge mode that is seconds after the first paint, so every
  launch now waits for the hook object; that is the app's own "fully started" signal and it removed a whole class of
  races. `waitForHooks: false` is for launches that are expected to exit (the single-instance test).
- **The fake bridge's default message timestamp is a fixed 2026-09-21T17:15:03Z** (`fake-bridge-db.ts`), which is BEFORE
  `live_from_ts` on a freshly seeded profile - an inbound without an explicit `ts` is silently treated as backlog and
  produces no item. Every spec passes `ts: new Date()`. This cost an hour; it is the first thing to check if a future
  ingest spec "does nothing".
- **The history sync is written before the app launches**, not while it runs: the in-process fake and the app both open
  `messages.db`, and 300 writes under the app's read lock only produce `SQLITE_BUSY`, not a better assertion. The
  property under test (`live_from_ts` ignores everything older) is unchanged.
- **`approval-first.spec.ts`'s green test asserts the ingest + invariant, not a rendered card**: with no usable provider
  the item stays `analysis='queued'` and the dashboard shows the "analysing" note rather than a card (that is the app's
  designed behaviour, `shared/state.ts` lists raw cards only when `held`/`failed`). The card-level assertions live in the
  blocked test, where a model exists.
- **The Google "Start" leg is never clicked** (see request 1). A test that could open a real browser at Google is worse
  than a red test.
- `seedGoogleCredentials()` writes a TESTONLY client so the fake calendar MCP becomes a real supervised child; that is
  what lets `tray-lifecycle.spec.ts` prove scenario (7) with TWO children rather than one.
