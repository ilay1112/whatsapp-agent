## Decisions / assumptions inside my files

1. **Check 7 hashes come from a new `vendor/whisper/SHA256SUMS`** written by `fetch-whisper.mjs` at fetch time (the zip is
   sha-verified first). T2 says "streamed sha256 equals `vendor/whisper/MANIFEST.txt`", but that file is a name list (llama's
   format, also read by `stagedCrtFrom`); a sidecar keeps both formats stable. The packaged files are compared with it; signing
   by electron-builder (no cert configured) did not alter any whisper byte.
2. **"Never mix" (check 7)** = no `ggml*` file of `<resources>\whisper` is byte-identical to ANY file of `<resources>\llama`
   (hash intersection, both directions covered). The CRT copies are excluded: ARCH-v2 12 wants each folder to carry its own
   identical copy.
3. **libopus licence text**: `opus-decoder@0.7.12` ships no copy of the libopus licence (it embeds libopus as WASM), and the
   brief allows no extra network fetch, so `resources/licenses/libopus-BSD-3.txt` reproduces the libopus `COPYING` (BSD-3 +
   the IETF patent-licence paragraph) from knowledge. **UNVERIFIED** against the exact libopus revision compiled into 0.7.12 -
   the copyright-holder line in particular. One fetch of `https://github.com/xiph/opus/blob/main/COPYING` (or the revision
   eshaz/wasm-audio-decoders pins) closes it; suggested as part of the release checklist.
4. **Check 8 compares** `out/main/manifest.json` (extracted from app.asar) with `vendor/models.pin.json` per id on
   `id, kind, magic, fileName, url, size, sha256` (LLM rows get `kind:'llm', magic:'GGUF'`, the pin script's shape), plus the
   rules applied to what SHIPS: `https://huggingface.co/<repo>/resolve/<40-hex>/<fileName>` only, no executable extension,
   only the three `mmproj-F16.gguf` pins (B18/F19 sizes), voice sizes/kinds/`GGML`, the VAD sha.
5. **Check 9** reuses the real server's `tools/list` objects from check 1 (no second spawn) and verifies the packaged
   `build/index.js` against `bundleSha256Patched` + each of the seven `patch.json` markers exactly once (the `etag` in
   `ALLOWED_EVENT_FIELDS` of ARCH-v2 12 is marker 6). Still `initialize` + `tools/list` only.
6. **Check 10** walks the whole unpacked tree; the forbidden-package scan of app.asar is at any depth and uses the full
   ARCH-v2 12 list (a superset of T2's seven: + `@discordjs/opus`, `node-opus`, prefixes `@napi-rs/`, `ffmpeg`).
7. **Check 11** also asserts each decoder package's declared licence (MIT x3, Apache-2.0) and `opus-decoder` = 0.7.12 (D-070).
8. **`/props.modalities.vision`** is not automated (T2 11, concern 11): it stays M-IMG-2.
9. **README status line** says "v2 feature set built, not yet released (package version still 0.1.0)" - no version change is
   allowed, and the release waits for the M-items. I did not print test counts there (they change with every run); the
   orchestrator may add the final numbers from `ops/PROGRESS.md`.
