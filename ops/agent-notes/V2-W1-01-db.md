- Deterministic: fixed clocks/ids, rollback journal while building, `VACUUM`, then `journal_mode=WAL` (a real v0.1.x file is WAL-mode;

  field): after a Node upgrade the "regenerable byte-identically" test fails until the file is regenerated and the sha updated.

## Dead ends / decisions worth knowing

- Heredocs with backslashes are mangled by this shell wrapper - scratch files were written with the Write tool instead.
- Considered adding an optional `now` to `retention.purge`'s parameter; rejected to keep the frozen signature - derived from
  `closedBefore` instead (documented in the code).
- Considered leaving a bad live policy row in place (pure read); rejected: it would block every future grant via the unique index.
- `rejectedDeltaTo` first used `JSON.parse` in a try/catch; SQLite's `json_extract` raises on a non-JSON row before JS ever sees it,
  so the guard moved into SQL (`CASE WHEN json_valid(...)`).

   call its `disable('purge')` (or `repos.autoPolicies.setState(id, {state:'disabled', reason:'purge', at})` + notify).
3. **V2-W2-01-compose** (`compose.ts` daily `runRetention`): unlink `result.mediaFiles` under `<userData>\media-cache\` after each run.
4. **V2-W1-07-media-voice** (`media/mediaCache.ts`): retention names the files of a purged row `<MediaCacheRecord.sha256>.jpg` and
   `<MediaCacheRecord.sha256>.thumb.jpg` (from `repos/retention.ts mediaFileNames`). Please store in `media_cache.sha256` exactly the
   hash your file names use (C2 1.4: `sha256(chatJid|waMsgId)`), or tell me the scheme so the helper follows it.
5. **Orchestrator (contract gap)**: `chats.mergeLidInto` must delete the @lid chat's action rows (`actions.chat_id` is frozen by
   `trg_actions_frozen`), and in v4 that cascades to `event_revisions` / `auto_decisions` / `auto_writes`. I defer the merge while an
   automatic write is undoable (bounded, I8), but after that window a merged event loses its revision history (manual Undo / Restore
   original become unavailable for it). A durable fix needs a contract decision (e.g. allow `chat_id` re-pointing in the frozen
   trigger for the merge, like migration 2 did for `retry_of`).
6. **Orchestrator (performance, optional)**: `items.byCalendarEventId` and `chats.withPolicies` (now also `auto_policy='never'`) have
   no fitting index (`ix_chats_policy` predates the v2 column). Tables are small; if SLOW_STATEMENT reports appear, a later migration
   could add `CREATE INDEX ix_items_event ON items(calendar_event_id) WHERE calendar_event_id IS NOT NULL` and widen `ix_chats_policy`.
