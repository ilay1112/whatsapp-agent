# v2 finalizer result (workflow ⑤)

## Changes made
- All 40 findings were checked. Where a claim could be checked offline, it was checked against the pinned bytes; no binary was run. F12 (no etag in the pinned calendar server), F17 (the SDK accepts only 405), F18 (29 call sites use the 3-argument markApprovedExecuting), F19, F21 (updateAllInstances forwards no headers and no sendUpdates), F22 (a stateless transport cannot be reused) and F26 were confirmed. None was rejected outright; F6 was merged into F27, and F6's 'rewrite waItem' option was rejected.
- docs/ARCHITECTURE-v2.md: edited B1, B4, B7-B10, B13, B14, B16-B20, B23-B25, B28, B30, I1', I6', I8-I11 and sections 3, 4.1, 4.3, 4.4, 5, 5.1, 6.3, 6.4, 7, 9.1, 9.2, 10-14, 16, 17 and 18. Added section 19, a register showing the verdict for F1-F40 and where each fix was applied. Every change is marked F<n>.
- Undo (F1, F2, F10): undo now follows the revision chain. The next undo candidate is the newest non-undo revision that has not been reverted and that sits behind only reverted or undo revisions. The drift check compares against the newest revision's post_etag/post_updated (new columns on event_revisions). Added item:restoreOriginal. The undo window and blocked_started for an automatic update or cancel are measured to the start of the slot being restored, not the attacker-chosen new start. An automatic move to an earlier time needs at least 24 h lead. Undoing an automatic write taints that chat for 7 days.
- Calendar patch (F12, F21, F25, F37): the vendored patch is now 7 insertions: status schema, body status, ifMatch schema, the If-Match header on the updateAllInstances patch call, a 412 branch, 'etag' in ALLOWED_EVENT_FIELDS, and etag in convertGoogleEventToStructured. A readback without an etag fails closed. sendUpdates on updates is documented as not a control; the control is 'no attendees'. stage-calendar-mcp.mjs gets a --patch-only offline mode for W1-02. The upstream PR is only prepared, not filed.
- Ownership and edits (F27, F6, F5, F9, F31): new items.event_origin_item_id is copied forward on every applied change and compared with the waItem tag, so a second change or an undo no longer fails CAL_EVENT_FOREIGN. An automatic update fails closed when there is no baseline (for example v1 events). Updates never send description. New checks content_rejected (title/location), multiple_events, and badge change_target_unclear.
- Database trigger (F4): 'user_toast' is accepted only on an undo payload that has revertOf. An auto approval must match the decision kind, come from an unexpired 'on' policy, carry approved_final_json equal to canonical_json, and never be an undo.
- Claude CLI (F7, F8/F15, F13, F14, F16, F17, F22, F23): cli:signIn spawns the exe directly, never through cmd.exe, and ClaudeExePathSchema now rejects % ^ & ( ) ! @ and '..'. Three env switches were added to turn off user memory and claude.ai connectors (names unverified, register U-C7). StructuredOutput is allowed on schema runs (U-C8). Version floor raised to 2.1.248. CLAUDE_MCP_CONFIG_MODE adds a pre-decided run_file fallback for the token (U-C6). The tool server answers 405 to an authenticated GET/DELETE and builds a new server and transport per request. S1 uses --system-prompt, with a W0 test that each prompt stays under 8 KB.
- Antigravity (F3, F20): agy runs with an app-owned profile at <userData>\agy-home, so the user's global MCP servers and hooks never load. If sign-in does not survive that, the fallback is the user's real profile behind a fail-closed preflight that refuses with a new CLI_UNSAFE_CONFIG error. agy gets its own stdin format (buildAgyStdinLine) and a new fake mode, global_mcp_present.
- Settings (F11): allowOverage and readTools.scope were removed from settings:set. They are set only through cli:setOverage and wa:setReadScope, which need a focused window and show a native confirmation before widening.
- Pipeline (F28, F32, F40, F33): the user's own message can now trigger an update (trigger_author='self'; no draft step, update only). Rejecting a change sets 'declined', and rule R13 stops the same change being proposed again. item:cancelEvent added. A duration-only change is a reschedule that keeps the start. Voice: notes predicted to take over 300 s are refused before starting (new VOICE_TOO_LONG_FOR_DEVICE), voice work is capped at 120 s per chat run (the rest is deferred), and VOICE_TIMEOUT is not retried automatically.
- Models and golden gates (F19, F24, F29, F36): a new MEDIA_MODEL_MANIFEST keeps the frozen gguf-download test green. The picture-model size comes from the manifest per tier. imagesPassed=false now means the picture is read but gets an amber badge and stays manual. New release gate M-GOLDEN-1, including a --feature v1 regression run. edits.jsonl grows to 27 rows (7 new: self-authored, duration-only, two live events, one title false positive).
- Contracts, UX and build plan (F34, F35, F38, F39, F18, F26): I10 reworded so 'Turn on now' is allowed after the native dialog. The gates constant in the tests spec now matches contracts. B24 gets its own acceptance test. The build plan names every v1 call site W0 must update to pass 'user' as the new approvedBy argument, and the colocated-test ownership rule now covers X.<suffix>.test.ts.
- Specs updated to match: v2-contracts.md (types, limits, errors, settings, IPC, CLI, tool server, exec, agent seams, repos, DDL/trigger, fakes, checklist, concern 21), v2-pipeline.md (S0, V0, routing, section 7, R13, S4, the G/K tables, section 11, provider table, golden rows, finalisation note), v2-tests.md (fakes, probe matrix, unit map, security groups 13/14/16/17/18/19/22, section 7, M-items, DoD, concern 15), v2-ux.md (C9/C15/C17 resolved, new section 17 with copy in both languages), v2-build-plan.md (rule 8, W0 steps 2-4, section 3 seams, W1 briefs, ownership row for build-resources, section 8 items 11-12, section 10 concerns).
- Ownership re-checked: no path gained a second owner and no source file was added; restoreOriginal, cancelEvent and confirmSetting go into existing W1-04 files. The only new file is the test src/main/agent/prompt.size.test.ts (W0, then W1-03 under the extended rule 8). My reasoning is in ops/agent-notes/v2-finalise.md.

## Rejected findings
- F6 option A (rewrite the Google waItem tag to the acting item on every update) and the 'any item of the same chat' relaxation: rejected. waItem is stable app identity (the fake calendar already flags update_event_identity_changed), and relaxing ownership weakens I9. F6 itself is accepted as a duplicate of F27 and fixed by items.event_origin_item_id.
- F12 option (b) (drop etag and If-Match, compare updated + sequence): not chosen. Option (a) keeps the real compare-and-set that C3 argued for.
- F31 full variant (run-scoped event_1..3 handles plus an app-pinned targetEvent S1 field): deferred to v2.1 (D-057). The cheaper variant (editableCount, change_target_unclear badge, multiple_events fallback) blocks the wrong-event automatic write now.
- F33 alternative 'separate low-priority V0 lane': not chosen. A predicted-time refusal, a 120 s per-run budget with deferral and a 300 s job cap bound the stall without a new queue.
