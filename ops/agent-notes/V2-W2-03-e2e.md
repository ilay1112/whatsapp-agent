## Decisions / assumptions

- **App clock anchor** = a MONDAY 07:00Z at least 7 days after the real date (not the fixed 2026-09-21 of the golden sets): the
  renderer validates events against its OWN real clock (only main sees WCA_NOW), so an anchor in the past made every proposed
  event "in the past" and "Add to calendar" disabled. 07:00Z keeps every automatic write outside the quiet hours.
- **Soft assertions** (`expect.soft`) are used ONLY where the expected behaviour is a product defect that would otherwise stop the
  rest of the flow; each has a message naming the expectation and is listed under REQUESTS. A soft failure still fails the test.
  The safety half of each scenario is always a hard assertion.
- Where the product reached a state by a different but documented user path, the spec follows the product (and says so):
  "Run a test" before "Use" for a CLI provider (C2 8 `llm:setProvider` requires a passed test, B12); "Refresh card" on a dirty card
  (UX 6, the v1 lesson); the AutoStrip collapses once nothing is undoable (UX2 3.1), so "Undone" is one "Show" away; revisions are
  numbered from the create (C2: rev 1 = create), so a manual reschedule shows "rev 2" where T2 10 writes "rev 1".
- Media downloads are NEVER clicked (see BLOCKED-BY): they would leave the machine.
- 20 s per inbound batch: `WCA_TIMERS.debounceMs` is not honoured (REQUEST 1), so specs deliver several chats at once.
