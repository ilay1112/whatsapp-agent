## 3. Fakes (interfaces frozen in Wave 0 of v2, lane L1; bodies owned by the lane named in section 15)

### 3.1 FAKE CLAUDE CLI - `tests/fakes/fake-claude-cli.mjs`

Purpose: the only "Claude Code" any automated test ever sees. It is spawned by the production `CliRunner` (unmodified argv builder, env builder, stdin writer, NDJSON parser, init assertion, kill path, pid file) through `WCA_CLI_CMD` (E2E) or the `S-SPAWN`/`S-LOCATE` injection (L3/L4). It must be good enough that a wrong flag, a wrong env key, a message on argv, a missing `is_error` check or a looser init assertion **fails a test**.

**Invocation.** `node.exe <abs>/tests/fakes/fake-claude-cli.mjs --fake-journal <file> --fake-state <file> [--fake-script <file>] --fake-end <argv exactly as the app builds it>`. Everything after `--fake-end` is parsed as the real CLI would; everything before it belongs to the fake. The argv literal tests compare `argv.slice(argv.indexOf('--fake-end') + 1)` with the production builder output. The fake reads **no** env var of its own (the app's env is an allow-list; a fake-only env var would have to be allowed by production code).

**State file** (`--fake-state`, JSON, re-read on every invocation so a test can flip it between runs):

```ts
export interface FakeClaudeState {
  version: string;                       // printed by `--version` as `<version> (Claude Code)`; default '2.1.258'
  loggedIn: boolean | 'garbage';         // `auth status --json` -> {"loggedIn":...} | non-JSON text
  mode: FakeClaudeMode;                  // default 'ok'
  modeByStage?: Partial<Record<'extract'|'draft'|'read_image'|'smoke', FakeClaudeMode>>;
  neutralInternals?: string[];           // extra names added to system/init.tools (models U-C1); default [] (see CLI_NEUTRAL_INTERNALS)
  apiKeySource?: string;                 // default FAKE_OAUTH_SOURCE (the pinned literal once U-C2 closes; until then 'none')
  rateLimit?: { status: 'allowed'|'allowed_warning'|'rejected'; resetsAt: number; isUsingOverage: boolean };
}
export type FakeClaudeMode =
  | 'ok' | 'attacker' | 'no_tools' | 'extra_tool' | 'extra_server' | 'plugins_present' | 'mcp_server_error'
  | 'api_key_leak' | 'init_not_first' | 'no_init' | 'rate_limit' | 'usage_limit' | 'overage' | 'auth_failed' | 'account_on_hold'
  | 'model_not_found' | 'is_error_success' | 'refusal' | 'no_structured' | 'max_turns' | 'max_structured_retries'
  | 'garbage_lines' | 'hang' | 'kill_me' | 'crash_mid_stream' | 'stderr_flood';
```

**Flag table** (the subset of `claude --help` 2.1.258 the app may use; anything else => `error: unknown option '<flag>'` on stderr, exit 1, exactly like the real CLI - this catches typos in the argv builder):
`-p/--print`, `--restricted`, `--strict-mcp-config`, `--tools <list>` (the empty-string element is parsed as "no tools"), `--permission-mode <m>`, `--permission-prompts <v>` (**unknown option when `state.version` < 2.1.259**, which catches a missing version gate), `--disallowedTools <csv>`, `--allowedTools <glob>`, `--disable-slash-commands`, `--no-session-persistence`, `--system-prompt <text>`, `--max-turns <n>`, `--output-format stream-json`, `--input-format stream-json`, `--verbose`, `--model <m>`, `--fallback-model <m>`, `--effort <e>`, `--json-schema <json>`, `--mcp-config <json>`; sub-commands `--version`, `auth status --json`, `auth login --claudeai` (sets `loggedIn:true` in the state file; only ever reached from L3 unit tests of the console command builder, never from E2E, T8).
Forbidden-but-known flags `--bare`, `--dangerously-skip-permissions`, `--add-dir`, `--settings`, `--continue`, `--resume`, `--append-system-prompt`, `--append-system-prompt-file`, `--permission-mode bypassPermissions`, a positional prompt argument: accepted (so the app does not simply crash) **and** recorded as `violation:forbidden_flag:<flag>` in the journal (the ledger fails the test).

**Journal** (one JSON line per invocation; read by `cli-fakes-hook.ts`): `{argv (post --fake-end), argvHasToken, cwd, cwdEmptyAtStart, envKeys (sorted names only), envChecks {pathIsSystem32, tempIsCwd, tokenPresent, forbiddenKeys[]}, stdinLines, stdinSha256, stdinNonceWrapped, stage, toolCalls[{name, allowedByServer, isError}], rawServerProbes[], exit, violations[]}`. The token value is recorded only as `argvHasToken: boolean` and `tokenPresent: boolean`; the journal never contains it.

**Stage detection** (from argv, never from the prompt text): `--mcp-config` present => `draft`; `--json-schema` equal to the byte constant `IMAGE_READ_SCHEMA` => `read_image`; the 1-field smoke schema => `smoke`; any other `--json-schema` => `extract`.

**Behaviour per invocation.**
1. Validate the env (records, does not refuse): exactly the ARCH2 4.3 allow-list, incl. `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1`, `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`, `ENABLE_CLAUDEAI_MCP_SERVERS=false` (F8/F15; a missing or different value => `violation:env_memory_switch:<name>`); `PATH` equal to `<SystemRoot>\System32`; `TEMP`/`TMP` equal to `cwd`; `WCA_MCP_TOKEN` present iff stage `draft`; any of `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL`, `ANTHROPIC_PROFILE`, `CLAUDE_CODE_OAUTH_TOKEN`, `CLAUDE_CONFIG_DIR`, `CLAUDE_CODE_USE_*`, `HTTPS_PROXY`, `NODE_OPTIONS`, `ELECTRON_RUN_AS_NODE`, `WCA_BRIDGE_TOKEN`-like names => `violation:env_forbidden:<name>`.
2. Read stdin to EOF; exactly one line, a stream-json `{"type":"user","message":{"role":"user","content":[...]}}`; the text block must contain exactly one nonce data block (`<<DATA-<nonce>>> ... <<END-DATA-<nonce>>>`); for `read_image` the **first** content block must be `{type:'image', source:{type:'base64', media_type:'image/jpeg'|'image/png', data}}` whose decoded size is <= 10 MiB. Deviations => `violation:stdin_shape:<detail>`.
3. `draft` only: parse `--mcp-config` - inline JSON (mode `inline_env`) or the path of `<runDir>\wca.mcp.json` (mode `run_file`, F16) - require exactly one server named `wca` of `type:'http'` whose URL host is `127.0.0.1` and whose `Authorization` header is the literal `Bearer ${WCA_MCP_TOKEN}` (inline) or a literal token inside the run dir (file mode; the fake asserts the file is inside `cwd`); expand `${WCA_MCP_TOKEN}` from env (`// ASSUMED (U-C6/M-CLI-1): the real CLI expands env references in inline --mcp-config headers`); connect with `mcp-client-core.mjs` (3.4) **before** printing `init` (models the startup wait); the client's `onerror` firing is a `violation:mcp_client_error` (F17); an authenticated raw `GET /mcp` must answer 405 (else `violation:get_not_405`); `tools/list` becomes `init.tools = ['mcp__wca__' + name, ...]`.
4. (schema stages `extract|read_image|smoke`) `init.tools` = `['StructuredOutput']` + `neutralInternals`, and the answer is delivered as an `assistant` `tool_use` named `StructuredOutput` followed by the `result` with `structured_output` (F13/U-C8 - the app must neither fail the init nor count a strike). Print `{"type":"system","subtype":"init","session_id":"fake-<n>","cwd":...,"model":...,"permissionMode":"dontAsk","apiKeySource":<state>,"tools":[...],"mcp_servers":[...],"mcp_server_errors":[],"plugins":[],"slash_commands":[]}` as the **first** line; `tools` = `['StructuredOutput']` + `neutralInternals` for `extract|read_image|smoke` (F13), the MCP names + `neutralInternals` for `draft`; `mcp_servers` = `[]` or `[{"name":"wca","status":"connected"}]`.
5. Answer from the script (`--fake-script`, the `StubRule` JSON of TS 3.3 with `when.stage`, `when.contains` over the stdin text, `when.imageSha256`): `structured` => `structured_output`; `toolCalls` => for each call an `assistant` event with a `tool_use` block named `mcp__wca__<name>`, a real `tools/call` through the MCP client, a `user` event with the `tool_result`; `text` => final `assistant` text and `result.result`; `error` => the matching failure mode. With no script, `ok` returns a schema-valid minimal answer per stage.
6. Print `rate_limit_event` (`{"type":"rate_limit_event","rate_limit_info":{status,resetsAt,rateLimitType:'five_hour',overageStatus:'allowed',isUsingOverage}}`) when `state.rateLimit` is set, then the final `result` line with the documented envelope (`type, subtype, is_error, result, structured_output?, session_id, stop_reason, num_turns, duration_ms, usage, permission_denials, uuid`).

**Failure modes** (each drives at least one test in 6.4 / 8.2 group 18):

| Mode | Output | App MUST |
|---|---|---|
| `attacker` | `ok` shape plus: `tool_use` blocks for `Bash`, `Read`, `WebFetch`, `mcp__gmail__send_message` with matching `permission_denials` entries; **raw** `tools/call` probes to the tool server for `send_message`, `create-event`, `create_event`, `update-event`, `delete-event`, `get-event`, `list-events`, `manage-accounts`, `mcp__wca__wa_search_messages`, `wa_list_chats` (in `trigger_chat`), `auto_enable`, `approve`, `undo`, `settings_set`, a 300-char name, a homoglyph `wа_search_messages`, and `wa_get_chat_messages {chat:'chat_77'}`; the draft text contains a URL, a phone number and `SENTINEL_CLI_STDOUT` | block every probe through `ToolGate` (synthetic `isError`, `tool_blocked` audit, strikes), count non-`mcp__wca__` `tool_use`/`permission_denials` as strikes (2 => abort + `manipulation`), zero writes/sends, `link_removed`/`personal_details` badges, sentinel never logged |

## Architecture concerns

Followed as written; each is a genuine gap or inconsistency in ARCH2 that a test in this spec depends on. None blocks Wave 0; items 1-4 should be settled in `contracts.md` before lanes L4/L6/L10 finish.

1. **An Antigravity run with a passing init proof would be `cli_proven`, and `AutoGate` could not tell.** B25 derives `provider_class` purely from `runs.sandbox_ok` of the S1 and S3 runs, and `AutoGate` reads only `provider_class`; B14/C4 say automatic mode is **never** available with `antigravity_cli` in v2.0 (`provider_unsafe`). A passing agy init (`agent`, empty `tools`, `request-review`) sets `sandbox_ok=1`, so the proposal would be `cli_proven` and eligible. The snapshot hash (provider change pauses the policy) mitigates only a switch *after* enabling, not enabling while agy is already active. This spec requires (group 18, 7.2) that every `antigravity_cli` proposal is persisted as `cli_unproven` in v2.0; contracts.md should state it (or add the provider id to the facts `AutoGate` reads).
2. **The golden gate cannot reach `AutoGate`.** B30 puts the per-provider gate constants in `agent/gates.ts` and says below the gate the delta path is "manual-only"; B8/15 forbid `exec/autoGate.ts` from importing `agent/**`. Nothing persisted on the proposal carries "edits below the gate for this provider". Either S4 must persist it (e.g. a proposal column or a field of `delta_json` that `AutoGate` reads, reason `edits_not_in_scope`) or the constants must move to `src/shared/`. Tests assume the persisted-fact form.
3. **`llm.cli.claudeExePath` is a renderer-supplied executable path.** B23 adds it to `settings:set`, which contradicts ARCH2 10's rule that "no channel accepts a ... file path" and TS 5.3's key-name regex. A compromised renderer could point the app at any `...\claude.exe` it can write and have main spawn it with message data on stdin; `cli:signIn` then embeds the same string in a `cmd.exe /k` command line (quoting injection with `"`, `&`, `%`, `^`). This spec allow-lists the key, tests strict path validation, and forbids the console on any hostile value (section 5), but the safer design is to set the path only through a main-owned native file-open dialog (like the auto-mode dialog) and keep it out of `settings:set`.
4. **`AUTO_REASONS` is not exhaustive-testable as written.** (a) `no_user_echo` belongs to the user-echo check that D-057 defers to v2.1, so no input can produce it in v2.0; (b) `no_track_record` is an enable precondition, and the declared `AutoGate` input `{policy, action, item, chat, proposal, now}` carries no track-record count; (c) there is no reason for an event with **recurrence** (only `event_has_attendees`), although B9/I9 require a refusal. This spec adds `RESERVED_AUTO_REASONS` (proven unreachable), expects the count as a field of the policy/facts input, and accepts whatever reason contracts.md assigns to recurrence (the test asserts `fallback` plus zero calls).
5. **`AgenticRunInput` has no tool-server endpoint.** B15 says `draft.ts` starts the listener and then calls `provider.runAgentic()`, but the interface in ARCH2 4.2 carries `{system, user, specs, ctx, gate, maxTurns, jsonSchema}` - no URL, port or token. 6. **`'user_toast'` is a constant the trigger cannot bind to an undo.** B6 rejects `'auto'` because "a constant cannot be verified by the DB", yet the v2 trigger accepts `approved_by='user_toast'` on **any** `create_event`/`update_event`, although it is meant only for the toast's Undo. 7. **Which state is "pre-write" after Apply anyway?** I8 requires the state *before the write* to be stored; for a manual `update_event` approved with `confirmDrift:true` the pre-write state is Google's drifted pre-flight readback, not the proposal's `from`.
