- **S0 additions** (deterministic): `media_type='audio'` rows are kept as `Message{text:'', mediaType:'audio'}` and are live triggers when `settings.voice.enabled` and a voice model is ready (else `held/waiting_llm` raw card "Voice message" with the download action); image rows are triggers when `settings.images.enabled`; `video`/`document`/`sticker` stay context-only. `items.trigger_kind` is set at item creation. **Self trigger (F28)**: an `is_from_me=1` text row (or `done` from_me transcript) that is not an app send, in a chat with an editable event (`findExistingEvent() !== null`), is a live trigger with `trigger_author='self'` (S3 skipped, only `update_event` may result - B20); without an editable event from_me rows stay non-triggers exactly as in v1.

### 5.1 Item state machine deltas

`event_state` gains `change_proposed` (a delta is pending on this item), `updated`, `cancelled`. `deriveState()`: `updated` and `cancelled` map to `in_calendar` (a cancelled card leaves the list 24 h later as `past`); `change_proposed` maps to `needs_reply`. `closed_reason='superseded'` is used for the source item of an applied change. A delta item is the ordinary open item of the chat (the partial unique index still guarantees one open item per chat); `linked_item_id` points at the source `in_calendar` item; on `update_event` success `applyUpdateSuccess()` moves `calendar_event_id`, `event_start_ts`, `event_revision+1`, `calendar_updated` **and `event_origin_item_id`** to the acting item and closes the source item `superseded`. `items.event_origin_item_id` (F27) is set to the item's own id when its `create_event` is `done` and is copied forward on every applied change, so the Google tag `waItem` (never rewritten, stable identity) always equals the origin of the chain: create -> change -> change -> undo keeps working. A rejected `update_event` sets the delta item's `event_state = 'declined'` (F32, B20 suppression rule).
